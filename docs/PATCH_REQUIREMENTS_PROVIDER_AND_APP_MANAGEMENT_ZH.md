# CC Switch 增强补丁需求（草案）

## 目标

在不重做 CC Switch 现有 Provider 与安装体系的前提下，补齐两个独立能力：

1. 导入本机已有模型服务配置，并按需共享给多个应用；
2. 将安装、启动、更新与卸载放回用户正在配置的应用页面。

面向用户的界面统一使用“应用”“工具”“模型服务”等词，不显示 **Runtime** 及其变体；该词仅可保留在内部代码和技术文档中。

## 补丁 1：导入本机配置并共享

### 现状与差异

CC Switch 已支持多个应用与“导入当前配置”，但导入主要围绕当前应用，模型服务配置也更接近“每个应用一套”。

增强后，导入流程应能发现本机已安装应用中的 Provider，并将导入副本按需共享到多个已支持应用，例如 Claude Code、Codex、Gemini、ZCode、DSH、Hermes、OpenClaw。

### 用户流程

```text
扫描本机已安装应用的配置
→ 展示发现的 Provider（来源、名称、Base URL、协议、模型、密钥是否已配置）
→ 用户勾选要导入的 Provider
→ 选择共享到哪些已安装应用
→ 展示将要写入的配置摘要
→ 用户点击“启用并应用”
```

### 约束

- 导入是复制，不修改来源应用的原始配置；界面需标记来源，例如“从 Codex 导入”。
- 共享不是立即静默写入：先形成待启用绑定，用户确认后才写入各目标应用。
- Provider、模型与账号/订阅登录分开管理；API Key 只保存到安全存储，界面只显示是否已配置。
- 模型选择器只展示当前应用实际可用的模型。

## 补丁 2：应用页内的安装与管理

### 位置与职责

在每个应用的 Provider 页面顶部放置紧凑、可置顶的“应用状态卡”。“关于/本地环境检查”保留为全局概览与批量升级入口；日常安装和管理不再隐藏在该页。

卡片显示：应用图标、安装状态、版本、是否已接入 CC Switch，以及对应操作。

### 状态与操作

| 状态 | 主操作 |
| --- | --- |
| 未安装 | `标准安装`、`AI 辅助安装` |
| 已安装，未接入 | `启动`、`更新/已是最新`、`卸载` |
| 已安装，已接入 | `启动`、`更新/已是最新`、`卸载` |
| 已安装但不可运行 | `修复安装`、查看日志 |
| 安装中或更新中 | 当前步骤、耗时、停止、日志 |

- “已接入”是配置状态；“已启动”是进程状态，两者不得互斥。
- CLI 没有可靠的常驻运行状态，按钮使用“启动终端”或“打开终端运行”，不显示“已启动”。
- 仅当 CC Switch 自己启动且仍在管理 Desktop/后台进程时，才显示“已启动”。
- “已是最新”是不可点击的状态标签；发现新版本才显示“更新”。
- 卸载使用红色描边按钮与二次确认；卸载只移除应用本体，不默认解除接入，也不删除 Provider、账号或配置快照。
- 安装来源未知时允许启动和接入，但更新/卸载降级为人工指引。

### Codex 的特殊展示

Codex 同时展示两个独立条目：

- **Codex Desktop**：安装状态、当前桌面端版本、`启动桌面端`、更新、卸载；
- **Codex CLI**：安装状态、CLI 版本、`启动终端`、更新、卸载。

Codex CLI 是内置小助手的执行基础；桌面端启动与 CLI 启动不可混用。

## 安装方式

### 标准安装

调用 CC Switch 已登记的安装映射和现有下载逻辑。只对已支持的应用开放，安装后必须重新检测实际路径与版本。

### AI 辅助安装

由 Codex CLI 提供受控自动化。用户先选择：

1. 安装目标：CLI、Desktop 或两者；
2. 安装位置：默认位置或自定义目录；
3. 版本：稳定版、最新版本或指定版本。

随后界面显示计划、来源、步骤、实时日志和最终检测结果；用户点击“确认并开始”后才执行。

安全边界：AI 只能依据已登记的应用安装能力、官方来源和允许的安装参数执行。无法确认的来源或方式必须降级为说明与复制命令，不得生成并执行任意 Shell 命令。

不同应用必须声明其能力：仅 CLI、仅 Desktop、两者皆支持、是否支持自定义目录、是否仅能下载安装包或只能手动指引。不能将“默认安装 CLI + Desktop”作为全局默认。

## 验收要点

- 已有电脑上的 Provider 可被扫描、导入、选择目标应用并显式启用。
- 导入不会改写来源配置；写入前可看见目标应用与配置摘要。
- 用户在单个应用页面即可完成安装、启动、更新、卸载与导入当前应用配置。
- Codex Desktop 与 Codex CLI 分开显示版本和启动动作。
- 所有安装、更新、卸载完成后均重新检测；命令返回成功但版本未变化时不能显示成功。
- 面向用户的新增界面中不出现 “Runtime”。
